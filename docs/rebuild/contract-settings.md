# 设置页与通知配置

> 前置：`contract-core.md`、`contract-skeleton.md`、阶段 0~4 前半段已上线。
> 目标：设置从弹窗变成像样的独立页面；Bark 能在网页上自己配；先做一条通知规则。

## 一、为什么重做

现在的设置塞在一个弹窗里（`app/layout/SettingsModal`），只有两块：个人资料、主题语言。输入框挤成一团，加不进新东西。

这次改成**独立页面** `/[lng]/settings`：左边分区导航，右边内容区，一屏一件事。

## 二、配色（已定）

改 `globals.css` 里的主题变量，**全站跟着变**，不是只改设置页。shadcn 组件本来就吃这套变量，不用改组件。

| 用途 | 色值 |
|---|---|
| 背景 | `#FAFAF9` |
| 卡片 | `#FFFFFF` |
| 主色（按钮、选中、链接） | `#1F6F5C` |
| 强调（警告、待办） | `#D97706` |
| 文字 | `#1C1917` |
| 副文 | `#78716C` |

调子：安静、不抢内容，像 Linear / Notion 那路。

深色模式的对应值自己配齐，保证对比度够（正文至少 4.5:1）。**不要只改亮色忘了暗色**——现有代码里有跟随系统的主题切换。

## 三、设置页的分区

| 分区 | 内容 |
|---|---|
| 个人资料 | 头像、昵称（把现有 ProfileTab 搬过来，重新排版） |
| 外观 | 主题、语言（把现有 GeneralTab 搬过来，重新排版） |
| **通知** | **新增**：Bark 配置 + 通知规则 |

原来的弹窗可以留一个入口跳到这个页面，或者直接去掉，自己判断哪个更顺。

## 四、通知配置

### 存哪

**按用户存数据库**，不再只靠服务器 `.env`。

新增集合 `userNotifySetting`（或挂在现有 user 相关表上，自己判断哪个更合适并说明理由）：

| 字段 | 说明 |
|---|---|
| `userId` / `userType` | 唯一 |
| `barkBaseUrl` | 用户填，形如 `https://<域名>/<设备key>/` |
| `barkKey` | 用户填，请求头 `bark-key` 的值 |
| `group` | 通知分组，默认 `AiToEarn` |
| `enabled` | 总开关 |
| `rules` | **数组**，一条规则一个对象。现在只有一条，但**结构上必须能放多条**，别做成一个布尔字段 |

规则对象：
```ts
{ type: 'draft_ready', enabled: boolean }   // AI 生成素材结束后通知
```

`.env` 里那套保留，作为**用户没配时的兜底默认值**。用户配了就用用户的。

### 密钥怎么处理

- **接口永远不回传 `barkKey` 明文**。读的时候只回掩码（比如只留后 4 位）和一个「已设置」标记
- 提交空字符串表示「不改」，提交新值才覆盖
- **任何日志都不许打印这两个值**
- 存库是明文（加密要引入密钥管理，这轮不做）。**这个取舍要写在代码注释里**，别让后来人以为是加密的

### SSRF 必须防（重要）

用户能填任意 `barkBaseUrl`，服务端会去请求它。**不防的话等于给了一个从服务器内部发请求的口子。**

要求：
- 只允许 `http` / `https`
- **解析出 IP 之后再判断**，拒绝：回环地址、私有网段（10./172.16-31./192.168.）、链路本地（169.254.，**云元数据地址就在这里**）、`0.0.0.0`、IPv6 的对应段
- 拒绝重定向到上述地址（跟随重定向时每一跳都要判）
- 超时 5 秒，响应体读取有上限
- 用域名时要在**真正发请求前**解析并校验，防 DNS rebinding 就尽力而为（至少解析一次并用解析结果连接）

拒绝时给人话提示，说清楚是地址不允许。

### 测试通知

设置页上要有一个「发送测试通知」按钮，调一个接口，用当前填的配置真发一条，把结果（成功 / 失败原因）显示出来。

- 这条通知的标题写明是测试
- 失败要说清楚是地址不对、key 不对、还是超时

### 接口

`@Controller('/settings/notify')`，要登录：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 读配置。**barkKey 只回掩码** |
| POST | `/` | 保存配置。barkKey 空串表示不改 |
| POST | `/test` | 用当前配置发一条测试通知 |

错误码 **20600 段**，i18n 补 `en-US` / `zh-CN`。

## 五、推送改成读用户配置

现有的推送服务（server 和 ai 各一份）现在读的是 `.env` 渲染进去的静态配置。改成：

1. **总开关 `enabled` 关掉 → 彻底不推**，不走任何通道
2. 总开关开着但用户没填地址 → 退回 `.env` 的默认值
3. 都没有 → 静默跳过（**行为不变**）

> 这条是踩过坑才写清楚的：初版契约写「用户没配**或没开**就退回 .env」，照字面实现的结果是——用户把总开关关了，还在继续收通知。这对用户是反直觉的，关了就该不收。规则开关是在总开关之下的第二层筛子，不是替代品。

**`.env` 兜底那条通道也必须走同一套 SSRF 防护。** 不能因为地址是运维配的就跳过每一跳校验——明文 http、域名过期被抢注、链路被劫持，都能让那个端点回一个 302 把请求带去内网。两个服务的行为必须一致。

**规则要生效**：`draft_ready` 这条关掉时，AI 生成完不推。

硬要求不变：推送失败绝不影响主流程、没配置静默跳过、5 秒超时、内容截断（标题 30 字、正文 100 字）。

## 五点五、前后端字段名以服务端为准

网页自己声明返回类型，**所以字段名对不上 TypeScript 一个字都不会报**，只能靠人核对。踩过一次：服务端回 `barkKeyMask` / `barkKeyConfigured`，网页写的是 `barkKeyMasked` / `barkKeySet`，编译全绿，跑起来掩码永远不显示、每次保存都被要求重输密钥。

规矩：**服务端的 VO 是权威**。网页照着抄，不要自己起名字。错误码表也一样——网页那份常量必须和 `response-code.enum.ts` 逐个对齐，不要凭印象编号。

## 六、UI 要求

**这是重点，用户明确说现在的输入框「不方便，也太挤了」。**

- 一律用现有的 shadcn 组件（`components/ui/` 下已经有 40 多个，**先翻一遍再写，不要重复造**）
- 表单用 `form.tsx` + `label.tsx` + `input.tsx`，密钥用 `password-input.tsx`
- **每个输入框都要有标签和说明文字**，不要只放个 placeholder 就完事
- 留白要够：分区之间、字段之间不要挤在一起
- 保存是显式按钮，**不要边打字边存**；没改动时按钮禁用
- 保存成功/失败用 `sonner.tsx` 给反馈
- 校验错误显示在对应字段下面，不要弹窗
- 手机宽度下不能横向滚动
- 六种语言文案补齐

**参考现有页面的排版习惯**（项目详情页、设备页都是这一轮做的），保持一致，不要在设置页另起一套。

## 七、验收

1. 设置页能打开，三个分区都能用
2. 填一个 Bark 地址和 key，点「发送测试通知」，手机收到
3. 刷新页面，key 显示成掩码，不是明文
4. 关掉「AI 生成素材结束后通知」这条规则，生成完不再推
5. 填一个内网地址（`http://127.0.0.1/`、`http://169.254.169.254/`）被拒，提示说人话
6. 全站配色变了，深色模式也对
7. 手机宽度下不横向滚动

# 附：配置管理从弹窗搬成页面

## 范围（用户明确圈定）

**只搬 UI，不碰功能。** 样式和交互跟设置页对齐，不再用弹窗。

## 先知道一件事：这个功能在当前部署里是坏的

配置管理是改服务端配置并能重启服务的工具。但：

1. **容器里配置是只读挂载**（`docker-compose.yml` 里 `./config/server.yaml:/app/config.yaml:ro`）。实测 `touch` 报 `Read-only file system`，**保存必然失败**
2. 就算能写也留不住——`deploy.sh` 每次都用 `.env` + `overrides/*.yaml` 重新渲染出 `config/*.yaml`，下次部署就被覆盖

根子上是两套模型打架：这个编辑器假设 `config.yaml` 是配置的源头，而当前部署的源头是 `.env` 和仓库里的 overrides。

**用户知情并选择这一轮只搬 UI。** 不要自作主张去改只读挂载、不要动部署脚本、不要试图让保存生效——那是另一个需要认真设计权限和审计的事。

## 要做的

- 新建独立页面，**不再用弹窗**。原来的 `app/layout/ConfigManagerDialog/` 里的逻辑搬过去
- **复用设置页的布局外壳和交互约定**：左侧分区导航 + 右侧内容区、显式保存按钮、标签加说明文字、校验错误显示在字段下面、反馈走 toast
- 导航里加入口，放在设置旁边
- 原来的弹窗入口改成跳转到这个页面，或者去掉
- 六种语言文案补齐
- 手机宽度下不横向滚动

## 不要做的

- 不要改后端 `libs/config-editor/`
- 不要改 `deploy/` 下任何东西
- 不要为了让保存成功而绕开只读挂载
- 不要把「保存会失败」这件事藏起来——失败时把服务端返回的真实原因显示出来就行，不要包装成「稍后重试」

# 附二：配置页右侧改成设置页的排版

## 用户原话

> 配置的右侧 也不要用 表格来做了，不好看，都按照 个人设置里的 那种 风格来

## 现在是什么样

`config/components/ConfigField/index.tsx` 第 212、433 行：

```
grid min-h-8 gap-2 py-0.5 pr-2 lg:grid-cols-[minmax(120px,180px)_minmax(0,1fr)]
border-b border-border/70 last:border-b-0
```

两列网格、行高 32px、上下内边距 2px、每行一条细分割线——就是表格。

## 目标是什么样

设置页已经有现成的外壳和字段范式，**直接复用，不要另写一套**：

- `settings/components/SettingsSection.tsx` 导出 `SettingsSection`（分区标题 + 说明 + 卡片）和 `SettingsCard`（卡片，`p-5 md:p-6`，可带小标题和说明）
- 字段范式看 `settings/components/NotifySection/index.tsx`：
  - 字段之间 `flex flex-col gap-7`
  - 每个字段：`FormLabel` + 说明 + 输入框**竖着堆**，标签和说明用 `space-y-1.5` 收在一起
  - 开关类：`flex flex-col gap-2 sm:flex-row sm:items-start sm:justify-between sm:gap-6`，左边标签说明、右边开关

## 必须同时解决的问题：页面会很长

服务端配置文件 7KB、上百个字段。照设置页那种留白一路排下去，页面长到没法用——**当初用密集网格是有原因的**。

所以不是单纯换排法，要一起做分组：

- 配置本来就有分区（左侧导航那些），**一个分区 = 一个 `SettingsSection`**
- 分区里的**嵌套对象 = 一个 `SettingsCard`**，用对象名当卡片小标题
- 嵌套超过两层的，**第三层起用折叠**（`collapsible.tsx` 已有），默认收起
- 字段多的卡片也可以整卡折叠，默认展开常用的、收起冷门的
- 如果现在有搜索/过滤，保留；没有的话**加一个**——上百个字段没有搜索找不到东西

## 其他要求

- **不碰功能**。读取、校验、保存、重启的逻辑一行不动。这轮还是只改样式和布局
- `ConfigJsonPanel`（JSON 视图）保留，它本来就适合密集展示
- 每个字段的说明文字：配置本身有 describe 的就用它，没有的**不要编**，留空
- 六种语言文案补齐
- 手机宽度下不横向滚动
- 对比度照 `debt-visual.md` 的规矩：正文 4.5:1、图标 3:1，亮暗都算，叠加后的真实值
