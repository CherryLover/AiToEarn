# 自定义 AI 技能

> 前置：`contract-core.md`。
> 目标：用户能自己传技能上来，存成文件、挂在宿主机上，重新部署不丢，传完下一轮对话就能用。

## 一、为什么

现在能用哪些技能是**写死的**：`apps/aitoearn-ai/src/core/agent/skill-init.service.ts` 里一个常量数组列着
15 个内置技能，服务启动时从镜像里复制到 `$HOME/.claude/skills`（`HOME` 被设成 `.claude-session`）。

两个后果：

1. 想加一个自己的技能，只能改代码、重新构建镜像、重新部署
2. 那个目标目录**在容器里**，容器每次部署都被 `rm --stop --force` 删掉重建，写进去的东西一律丢失

## 二、存哪（这一条不许改成数据库）

宿主机 `${DATA_DIR}/skills`，挂进 `aitoearn-ai` 容器的 `/data/skills`，**读写**。

技能是文件不是记录：它的内容就是一个目录（入口 Markdown 加参考资料、脚本），Agent 运行时是按文件读的。
塞进数据库意味着每次跑之前要先把它捞出来写成文件，凭空多一层，还多一个「库里有、盘上没有」的失配状态。
和项目物料同一个道理（见 `deploy/oci/README.md` 的「项目物料目录」）。

`deploy.sh` 负责在 compose 之前把这个目录建出来，和 `${DATA_DIR}/projects` 一样。

## 三、归属：部署级全局

**任何登录用户传上来的技能，这个部署里所有的 AI 对话都能用。**

不做按用户隔离。理由：技能描述的是「这套系统会干什么」，属于部署的能力，不是某个人的私有数据；
这个 fork 是自部署、登录用户可控的场景，按用户切开只会让「为什么我传的他用不了」变成新问题。

**但这件事必须在上传界面上写清楚**，人得知道自己传的东西是全局生效的。

## 四、一个技能长什么样

**一个技能 = 一个目录，也就是标准技能包：**

```
skill-name/
├── SKILL.md        入口，frontmatter 有 name、description
├── references/     参考资料（Agent 按需读）
├── scripts/        脚本（目前只存不跑，见第九节）
└── assets/ ...     其他任意子目录
```

上传收两种格式：

| 格式 | 上限 | 落盘 |
|---|---|---|
| **`.zip` 技能包（主格式）** | 包本身 ≤ **10 MiB** | 整包解到 `/data/skills/<name>/` |
| 单个 `.md` | ≤ **64 KiB** | `/data/skills/<name>/SKILL.md`（和以前一样） |

扩展名以外的一律拒（`SkillFileInvalid`）。和内置技能在磁盘上的形状完全一致。

### 包里哪一层是技能根目录

先把 `__MACOSX/` 开头的条目和任意层级的 `.DS_Store` 当没看见（macOS 打包顺手带进来的），然后只看文件：

1. `SKILL.md` 就在包根目录 → 包根就是技能根（`cd skill && zip -r x.zip .` 打出来是这样）
2. 所有文件都在同一个顶层文件夹下，且它里面有 `SKILL.md` → 剥掉这一层（访达「压缩」、`ditto --keepParent` 打出来是这样）
3. 其他情况 → 拒，`SkillEntryMissing`：多个顶层文件夹、顶层文件夹旁边还有散文件、`SKILL.md` 藏在两层以下、
   文件名大小写不对（Agent 只认 `SKILL.md`）

空文件夹不带内容，不参与判断。

### 名字

**技能名一律取 `SKILL.md` frontmatter 里的 `name`**，上传的文件名、包里的文件夹名一概不管；
落盘目录拿校验过的 name 重新拼。

frontmatter 必须有：

| 字段 | 规则 |
|---|---|
| `name` | 目录名，`^[a-z][a-z0-9-]{1,38}[a-z0-9]$`，不许连续 `-`，**不许和 15 个内置技能重名** |
| `description` | 一句话说明它干什么、什么时候用。技能是靠这句话被匹配到的，空的等于传了个永远不会触发的东西 |

包里的 `SKILL.md` 和单独传的 `.md` 一个口径：不超过 **64 KiB**（超了同样是 `SkillFileTooLarge`）。

### 同名

同名视为覆盖，但要在接口上明确（`overwrite` 参数），默认不覆盖，避免手滑顶掉别人的。

**覆盖 = 整个目录换掉**：旧包里有、新包里没有的文件不会留下（用 `.md` 覆盖一个技能包也一样，只剩新的 `SKILL.md`）。
只剩个空壳目录（没有 `SKILL.md`，比如上次半路失败的残留）不算已存在，直接顶掉。

### 原子落盘

Agent 同步时要么看到旧的整包、要么看到新的整包，看不到解了一半的东西：

1. 先解 / 写进 `/data/skills/.tmp-<随机>/`（同一个文件系统，rename 才是原子的）
2. 整包校验通过、拿到 name 以后，rename 成 `/data/skills/<name>`
3. 覆盖时先把旧目录 rename 成 `.trash-<随机>`，新的换上去再删 trash；换失败就把旧的挪回来
4. 任何一步失败，临时目录整个删掉

删除同理：先 rename 成 `.trash-<随机>` 再删。**以 `.` 开头的目录在列表和同步里一律跳过**，中间状态谁都看不见。

## 五、怎么生效

`SkillInitService` 把技能摊进会话技能目录 `<cwd>/.claude-session/.claude/skills`（即 `$HOME/.claude/skills`，
代码里是 `resolveSessionSkillsDir()`，第七节的只读口子用的是同一个）：

1. 把镜像里的 15 个内置技能复制过去
2. 再把 `/data/skills/*` 复制过去（真目录、不以 `.` 开头、根下有 `SKILL.md` 的才算）

规则：

- **整目录递归复制**，内置和自定义都是；只复制普通文件和目录，**软链一律跳过**；文件权限跟着带过去（scripts 的 0755 不丢）
- **复制某个技能前先删掉目标里的同名目录**，否则覆盖上传后旧包里多出来的文件会一直残留
- **复制完把目标里既不是内置、也不在 `/data/skills` 里的条目删掉**：删掉的技能不能还被 Agent 读到
- `/data/skills` 读不了（不是不存在）时不做这一步清理：宁可留着旧的，也不能因为一次读失败把所有用户技能撤掉
- 一个技能复制失败只打日志，不拖累其他技能

**内置的先复制，用户的后复制，但用户的不许覆盖内置的**——重名在上传那一关就挡掉了，
这里再挡一次是兜底：镜像升级加了新内置技能、恰好和某个已存在的用户技能同名时，
内置的必须赢，否则一次镜像升级会被一个旧文件悄悄改掉行为。

上传或删除之后**立刻重新跑一次同步**，不用重启服务，下一轮对话就能用。删除接口只删 `/data/skills` 里那份，
会话目录里那份交给同步去清，不再单独手删。

## 六、接口

挂在 `aitoearn-ai` 上（nginx 已经把 `/api/ai/` 路由到这个服务），前缀 `/ai/skills`，全部要登录。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/ai/skills` | 列出全部技能：内置的和用户传的一起返回，各自标明来源，并列出包里的文件 |
| POST | `/ai/skills` | 上传一个 `.zip` 或 `.md`，`multipart/form-data`，字段名 `file`，另有 `overwrite`（`'true'` / `'false'`） |
| DELETE | `/ai/skills/:name` | 删掉一个用户技能。**内置的删不掉**，服务端拒绝 |

返回的 `SkillVo`：

| 字段 | 说明 |
|---|---|
| `name` | 技能名，同时是目录名 |
| `description` | frontmatter 里的 description |
| `builtin` | 内置的只能看，自定义的能删 |
| `updatedAt?` | 自定义技能的最后修改时间；内置的没有 |
| `files` | 技能根目录下所有文件的相对路径：posix 分隔、按字符串排序、包含 `SKILL.md`，最多 500 条。内置和自定义都有 |

错误码用 **20900 段**：

| 码 | 名字 | 什么时候 |
|---|---|---|
| 20900 | `SkillNameInvalid` | frontmatter 里的 name 不合规 |
| 20901 | `SkillNameReserved` | 和内置技能重名 |
| 20902 | `SkillFrontmatterMissing` | 没有 frontmatter，或缺 name / description |
| 20903 | `SkillFileTooLarge` | zip 超 10 MiB、`.md` 超 64 KiB、包里的 `SKILL.md` 超 64 KiB（multer 那层的超限也转成这个码，不回裸 413） |
| 20904 | `SkillFileInvalid` | 扩展名既不是 `.zip` 也不是 `.md`，或者没传文件 |
| 20905 | `SkillAlreadyExists` | 同名已存在且没勾覆盖 |
| 20906 | `SkillNotFound` | 要删的技能不存在 |
| 20907 | `SkillBuiltinReadonly` | 内置技能只能看 |
| 20908 | `SkillStorageUnavailable` | 技能目录读写失败（多半是没挂上） |
| 20909 | `SkillArchiveInvalid` | 压缩包坏了，或含越界 / 不安全路径、软链、加密条目、同名条目 |
| 20910 | `SkillArchiveTooLarge` | 解压后总量超 30 MiB、文件超 500 个、单个文件超 10 MiB |
| 20911 | `SkillEntryMissing` | 包根目录或唯一的顶层文件夹里找不到 `SKILL.md`（含多个顶层文件夹） |

## 七、安全（这一节是重点）

**技能是写给 AI 看的指令。允许上传技能，等于允许登录用户往 AI 的执行上下文里注入指令。**

这不是能靠校验完全消除的风险，只能限定边界：

- **目录名严格白名单**，正则之外一律拒，杜绝 `../` 之类的路径穿越
- **落盘路径必须重新拼**：拿校验过的 `name` 去 join 根目录，绝不直接用上传来的文件名或包里的文件夹名
- **不许覆盖内置技能**
- **大小上限**，防止把磁盘写满
- **界面上明说全局生效**，让人知道自己在改的是所有人的 AI

### zip 的安全措施

解压是这条链路上最容易出事的一环（zip slip、软链、压缩炸弹、头部说谎）。解压库用 **yauzl**：
读中央目录、按条目流式解压、给得出每个条目的 unix mode（判软链要用）；fflate 这类一次性解进内存的库做不到后两条。

| 风险 | 措施 |
|---|---|
| 条目路径越界（zip slip） | 拒绝绝对路径、任何一段是 `..`、反斜杠、盘符（`C:`）、NUL 及其他控制字符、空段；统一成 posix 相对路径再用；拼出来的落点 `path.resolve` 后必须还在临时目录里。yauzl 开了 `strictFileNames`，自己也先挡一遍 |
| 软链 | **一个软链都不建**：所有条目按普通文件写（`wx` 打开，路径上已有东西就失败，不会顺着它写出去）；unix mode 标着软链、设备、管道的条目整包拒 |
| 压缩炸弹 / 头部说谎 | **按实际解出来的字节数累计**，单文件或总量一超立刻掐断流；zip 头里声明的大小只拿来提前拒掉老实的大包，不拿来放行。yauzl 的 `validateEntrySizes` 也会在实际字节数超过声明值的那一刻报错（按 `SkillArchiveInvalid`）。单个条目最多在内存里攒 10 MiB |
| 上限 | 包 ≤ 10 MiB；解压后总量 ≤ 30 MiB；文件数 ≤ 500（不含目录、`__MACOSX`、`.DS_Store`）；单文件 ≤ 10 MiB；`SKILL.md` ≤ 64 KiB |
| 条目撞名 | 同名两份、`a` 既是文件又是目录，整包拒 |
| 加密 / 不认识的压缩方式 | 整包拒 |
| 权限 | 文件 0644，`scripts/` 下的 0755，目录 0755 |
| 解到一半失败 | 全在 `.tmp-<随机>/` 里，失败整个删掉，正式目录不受影响（见第四节「原子落盘」） |

暂时不做的（要做得另开一轮，别顺手加）：

- 不按用户隔离
- 不审查技能内容。内容审查得靠人看，接口层做不了
- 不跑 `scripts/`（见第九节）

## 八、Agent 怎么读到技能包里的文件

Skill 工具只把 `SKILL.md` 注入上下文，里面写着「细节去读 `references/xxx.md`」——Agent 得自己用 Read 去读。
可会话技能目录在 `$HOME/.claude/skills`，**既在项目目录外、又带 `.claude` 段**，
项目对话里的路径校验（`ProjectWorkspaceService.checkToolInput`）原本两条都会拒，references 等于白传。

所以开一个**精确的只读口子**：

| | 放行 / 拒绝 |
|---|---|
| `Read` 的 `file_path`、`Glob` 的 `path`、`Grep` 的 `path`，真实路径落在会话技能目录内（含技能目录本身） | 放行 |
| 同上但路径还不存在 | 拿最近一层真实存在的祖先去解析、剩下的按词法拼回去，落在里面就放行（读不到是工具自己的事） |
| `Write` / `Edit` / `NotebookEdit` 指向技能目录 | **照旧拒**：技能只能从上传接口进来 |
| `<技能目录>/../settings.json`、会话目录下的其他配置 | **照旧拒**：真实落点不在技能目录里 |
| 技能目录里一个指向外面的软链 | **照旧拒**：按真实路径判断 |
| 项目自己的 `.claude/`（含 `.claude/skills`） | **照旧拒** |
| `Glob` 的 `pattern`、`Grep` 的 `glob` | 规则不变：绝对路径和带 `..` 的照旧拒。要列技能目录，就把它当 `path` 传 |
| 技能目录本身被换成软链 | 口子整个关掉（否则指向 `/` 就等于全开） |

为什么这是安全的：只读；`SKILL.md` 本来就会被 Skill 工具整篇注入上下文，references 的用途就是给 Agent 读的，
读它不多泄露什么；只限这一个目录，按真实路径判断，别处的 `.claude` 配置一个都碰不到。
拒绝信息里会告诉模型「技能目录只能读」，免得它反复试。

不带 projectName 的任务本来就没有这层路径校验，不受影响。

## 九、scripts 目前跑不了

`scripts/` 会被保存（0755）、同步进会话技能目录、Agent 能 Read，**但跑不了**：
Agent 的工具表里没有执行命令的工具（刻意不开 Bash，见 `PROJECT_EXTRA_TOOLS` 的注释），这一轮也不加。

要开得另外评估：允许技能里的脚本执行，等于**允许任何能传技能的登录用户在服务器上执行任意代码**，
这比「往 AI 上下文里注入指令」严重得多，至少要先想清楚沙箱、权限、审计，不能顺手加。

## 十、网页

设置页（`/[lng]/settings`）加一个分区「AI 技能」，和现有分区一样的排版：

- 列出全部技能，内置的和用户传的分开标，能看每个技能包里有哪些文件
- 传一个 `.zip` 技能包或单个 `.md` 上来；重名时问一句要不要覆盖（覆盖是整个换掉）
- 用户传的能删；内置的只能看
- 分区开头就写明：**这里传的技能对所有人生效**

各语言文案补齐（`de` / `en` / `fr` / `ja` / `ko` / `zh-CN`）。
