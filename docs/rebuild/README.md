# 重做：契约文档

> 这套文档是多个 Agent 并行开发的**唯一事实来源**。动手前必须完整读过，实现时以契约为准。
> 契约与代码冲突时，先停下来提出问题，不要自作主张改契约。

## 背景一句话

把这个 fork 从「多平台发布器」改成**以 Project 为单位的内容运营中枢**：

```
真实物料沉淀 → AI 提炼发布方向 → 按方向生成内容 → 派任务执行发布
      ↑                                                      ↓
      └──────────── 数据回流，好的方向继续深入 ←──────── 定时采集数据
```

完整背景、决策依据和分阶段计划见 `~/Code/Docs/OBCC/0201_Projects/aitoearn-fork.md` 的「重做方案」一节。

## 开工须知

1. **先读 `contract-core.md`，再读自己阶段的契约，再动手。**
2. **只碰分配给你的目录**。契约里每个任务都写死了可碰文件范围，越界会和别的 Agent 撞车。
3. **照抄仓库现有写法**，不要引入新的框架、新的状态管理、新的请求封装。`contract-core.md` 里列了范式。
4. **改完要能编译**：
   - 后端 `cd project/aitoearn-backend && pnpm nx run aitoearn-server:build`
   - 网页 `cd project/aitoearn-web && npx tsc --noEmit`
5. **不要自己部署**，不要推分支，不要提交。做完汇报改了哪些文件、编译结果如何，由调度方统一验证和上线。
6. 契约没写到的细节，按仓库现有习惯做，并在汇报里点出来。
