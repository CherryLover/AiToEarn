# 项目 AI 对话面板

项目详情页右侧那条常驻对话。方向和内容都在这里聊出来，标签页上的按钮只是往这条对话里发一句话。

## 目录结构

| 文件 | 说明 |
| --- | --- |
| `index.tsx` | 面板外壳：头部、消息区、输入区，以及会话切换 |
| `useProjectChatSession.ts` | 这个项目当前聊到哪一条会话：解析、新开、切换、本地记忆 |
| `ProjectChatHistory.tsx` | 这个项目的历史会话列表 |
| `useChatPanelWidth.ts` | 面板宽度：拖左边框改，收进上下限，记在浏览器本地 |

## 为什么是常驻栏而不是弹窗

想法多半是聊出来的：先说个模糊的念头，AI 问两句，补点材料，才谈得上提炼方向。
原来的「让 AI 提炼方向」是个一次性弹窗，只能单向发一次、跑完就没，聊不了。

面板挂在**项目详情页那一层**，不在「方向」标签页里：切到「生成」标签页，同一条对话还在。
宽屏（≥1280px）时它是正常的一列，把主体内容挤窄而不是盖住——人要一边看方向列表一边聊；
窄屏才退化成盖上来的抽屉加遮罩。

## 宽度可拖

左边框是拖拽手柄，拖着改宽度，松手记在浏览器本地（一个全局键，不按项目分：
同一个人在哪个项目都想要一样的宽度）。双击恢复默认，聚焦后左右方向键微调（按住 Shift 走大步）。

三条限制：

- 不小于 320px，再窄消息就堆成一条线
- 不大于 880px
- **不超过视口的一半**。面板是来让位的，拖到把主体内容挤没了就本末倒置；
  窗口被拖窄时也会跟着收，所以换台小屏机器不会打开就是半屏面板

手柄只在宽屏出现。窄屏那是盖上来的抽屉，占满宽度，没什么可调的——
所以断点交给 CSS：hook 只把宽度以 `--chat-panel-width` 变量给出去，className 里用 `xl:` 才套上。

**面板在宽屏必须是 `relative` 不能是 `static`**：手柄是绝对定位的，
`static` 不是定位上下文，手柄会跑去贴 body 的左边缘（屏幕外面）。

## 会话怎么组织

**一个项目一条当前会话，可新开，可翻历史。**

- 打开面板：先看浏览器本地记的那条；本地没有就按项目名去服务端拉最近一条
- 发消息：有当前会话就续聊（带 `taskId`），没有就新建
- 「开一条新的」：清掉当前会话，下一条消息才真正建任务
- 「历史对话」：服务端按 `projectName` 筛出来的列表

会话归属项目是**服务端存的**（任务记录上的 `projectName`，建任务时写入，续聊不改）。
本地那份只是快捷方式：换个浏览器、或者本地记的那条被删了，也能从服务端重新找回来。

## 复用了什么

除了外壳和会话切换，这个目录几乎不写实现：

- 消息流、工具调用、多轮续聊 → `@/store/agent`
- 消息气泡、输入框、工具详情 → `@/components/Chat`
- 会话加载、断线轮询、滚动控制 → `@/components/Chat/hooks`

这三样原来住在聊天页私有目录里，为了这个面板按 `components/Chat/README.md` 的放置规则提了上来。
**不要因为面板要点什么就在这里再抄一份聊天逻辑。**

## 和标签页的接线

面板不认识方向，也不认识草稿，只认两个回调：

```
标签页 → onAskAi(prompt)   把一句话丢进来，面板会顺手打开
面板   → onTaskFinished()  一轮跑完（不管成没成）通知页面
```

页面收到 `onTaskFinished` 就把 `aiRunSignal` 加一，方向页拿它去登记文件并刷新，
生成页拿它去刷新草稿列表。面板不负责知道该刷新谁。

## 边界

- `pendingPrompt` 靠自增的 `at` 去重，同一毫秒点两次也各发一次；发出去就回调 `onPromptConsumed` 清掉
- 没有会话时传给 `useChatState` 的是 `'new'`，它认这个值，会读当前活跃任务的消息——
  这样刚发出第一条、真实 `taskId` 还没回来的时候，界面上也立刻有东西
- 项目名通过 `ProjectScopeProvider` 交给底下的工具调用展示，用来把服务器绝对路径收成项目内相对路径
- 归档项目不给对话入口：接口在服务端一律拒绝，开出来也只能报错
- 面板关掉任务照样在跑（SSE 挂在 store 的 TaskInstance 上），重开靠增量轮询接上
